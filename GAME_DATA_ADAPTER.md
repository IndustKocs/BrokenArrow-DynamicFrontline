# Доступ к игровым данным

`IGameMatchContextProvider` поставляет текущий MatchId, provenance активной базы, roster двух команд, ревизии карты/навигации, DataOrigin, признак доверенного полного контекста и ID игрового потока. Ни один из этих параметров не восстанавливается догадкой из ближайших юнитов. Для live неизвестный provider оставляет мост недоступным.

`IGameObjectFeed` возвращает GameObjectBatch: ревизию, время, Complete и handles. Handle содержит LuaUnit только на уровне доступа, CanonicalUid и LifecycleStamp. Источник обязан определить namespace UID (например, проверенный NetID mapping), последовательность spawn/despawn и полноту census. LuaUnit.UID и NetEntity не считаются автоматически одним идентификатором.

ReadOnlyComponentInspector использует исследованные имена UnitComponent.Owner/UnitData, Units.Id/Role, IPlayerInfo.UID/TeamUid/TeamSide, InfantryUnitComponent.AliveSoldierCount, HealthComponent.CurrentHealth/MaxHealth, StressComponent.CurrentStressValue/MaxStress/CurrentStressLevel, Has<LoadedComponent>/Has<InfantryLoadingComponent>, LuaUnit.GetPosition/IsAlive и Entity.IsAliveVersion. Читается только getter CurrentHealth; setter никогда не вызывается. Has/Get отражением кэшируют MemberInfo/MethodInfo, но реальные ref-return IL2CPP-обёртки ещё не проверены.

Порядок: read-only инспекция на заявленном игровом потоке → проверка контекста/данных → полный копируемый RawGameFrame → валидация и нормализация → InternalSimulationSnapshot. ECS-ссылки, Span и borrowed buffers не покидают A. Inspector принимает отдельные providers visibility, собственного Deserting и death lifecycle. Без проверенного death provider активная сущность получает Unknown и не допускается к расчёту. Нельзя приравнять IsAliveVersion к отсутствию DeathComponent/RemoteDeath.

GameUnitIdentityResolver хранит собственные поколения. Для присутствующего UID с тем же LifecycleStamp поколение сохраняется; исчезновение из **принятого полного** снимка, новый stamp или оживление после зафиксированной смерти увеличивают generation. Неполный/отклонённый снимок не меняет registry. Новая сессия создаёт новый resolver. История поколений хранится до конца матча, чтобы повторный UID не совпал с прежним. Это не обнаруженное поле игры. Если исходный registry пропустит despawn+respawn между снимками и выдаст прежний stamp, адаптер сам не сможет доказать замену — runtime blocker.

Infantry-поля nullable для техники. Для активных ролей 30–36 отсутствие состава/здоровья/стресса означает неполный снимок; цифры не восстанавливаются из процента HP. Техника может быть relay только при явном AllowNonInfantryRelay; Core получает HasInfantry=false и отдельную активность, а не фиктивного солдата. Loading исключает участие по умолчанию; AllowLoading — явная настройка профиля. Полное разделение загрузки/выгрузки ещё требует подтверждённых игровых producers.

Валидация отклоняет дубли UID, пустые stamps, неизвестную команду, противоречивый roster, NaN/Infinity, координаты вне доступной маски, недопустимые HP/стресс, неверные ревизии и отрицательное время. Снимок содержит WorldPosition, 2D Position, PositionSource/PositionAgeMilliseconds, raw статус и причину исключения. Возраст пока диагностический: универсальный допустимый TTL позиции не утверждён. Для full-state расчёта нужен доверенный исполнитель; локальный allied-only reader не должен маркировать свой набор Complete для глобального ядра.

GameTeamResolver объединяет только явно переданные Player UID → Team UID/Side. В каждой стороне допускается до пяти игроков; стороны 0/1 различны, нейтральные/наблюдатели исключаются. Owner, network owner и TeamSide не взаимозаменяемы. CoordinateTransform переводит world X/Z относительно WorldOrigin с Scale; высота Y передаётся отдельно при обратном преобразовании. Мини-карта не используется как world space.

GameTerritoryMapProvider требует заданную маску, начальных владельцев, ProtectedOwners и корни. Прямоугольник без подтверждённой маски не создаётся автоматически. В fixture начальные полосы и защищённые корни симметричны; защищённые клетки не захватываются и не оспариваются чужой командой. Корни копируются на инициализации и никогда не следуют за фронтом.
