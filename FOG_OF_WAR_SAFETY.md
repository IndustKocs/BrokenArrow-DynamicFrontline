# FOW и границы диагностики

Внутренний InternalSimulationSnapshot содержит полный доверенный снимок. Он не является сетевым DTO. TeamSafeProjection строит отдельный TeamSafeDiagnostic с идентификатором матча, командой получателя, публичным временем и только собственными подразделениями: локальный handle, definition ID, позиция, alive, nullable soldier count и loading. Сериализация проверяет получателя и матч.

Не экспортируются вражеские сущности, глобальные UID/generation, source revision, unknown profile count, rejected snapshots, navigation counters, граф, статус окружения, логистика и территория. Даже собственный статус окружения способен раскрыть скрытого противника: поэтому недостаточно просто удалить чужие узлы из полного графа. Handles выдаются по собственным сущностям отдельно для каждой команды. Публичный tick должен приходить от независимых часов представления, а не от числа принятых полных снимков.

Тесты сравнивают байты командного JSON при изменениях скрытых врагов: позиции, состава, поколения и состояния. Этот тест проверяет содержимое DTO; он не доказывает отсутствие сетевых timing side channels, наблюдения за процессом, файловыми правами или неавторизованного вызова внутренних API. Сетевой транспорт пока не реализован.

GameVisibilityAdapter различает подтверждённый контакт и прочие признаки. Даже подтверждённые враги в текущую минимальную проекцию не включаются. VisibleTo, WasDetectedOnce, Shootable, маркер цели и PotentialSee не считаются взаимозаменяемыми разрешениями на экспорт. Проверенный team-scoped API контактов остаётся блокером расширения проекции.

Developer Debug разрешён только при явном включении и только для Synthetic/RecordedFixture. LiveReadOnly всегда отклоняется. Полный HTML содержит искусственные данные и явно помечен Synthetic. Team Safe HTML содержит только минимальные собственные данные; пустые массивы графа и территории — схема старого renderer, а не очищенный полный снимок.

Стабильный публичный статус не включает внутреннюю причину сбоя. Подробная диагностика предназначена для автономной разработки. Перед реальной передачей требуется отдельный аудит транспорта, частоты сообщений, адресата, логов и доступа к файлам.
