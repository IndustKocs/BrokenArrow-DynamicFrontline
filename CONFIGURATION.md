# Конфигурация прототипа

`config/frontline.example.json` читается через `FrontlineConfiguration.Load`. Он содержит Rules и явные Profiles. JSON предназначен для примера и тестов, а не для окончательного баланса. Включать настоящие Unit ID без проверки нельзя. При несовместимых изменениях повышайте Version. Коллекции профилей копируются в каталог; дубли ID отклоняются.

| Параметр Rules | Пример | Домен / назначение |
|---|---:|---|
| Version | frontline-poc-0.1-synthetic | Непустая строка; идентифицирует правила в DTO |
| TickMilliseconds | 250 | Целое 1…60000; один фиксированный расчётный шаг |
| CalmCoefficient | 1 | Конечное ≥0; Kstate для Calm |
| ShockCoefficient | 0.5 | Конечное ≥0; Kstate для Shocked |
| PanicCoefficient | 0 | Конечное ≥0; настраиваемое подавление влияния в панике |
| LocalRadiusPerSqrtInfluence | 4 | Конечное ≥0; масштаб sqrt(P), ноль выключает локальные круги |
| MaximumLocalRadius | 30 | Конечное >0, верхняя граница радиуса |
| CaptureThreshold | 16000 | Положительное long ≤ long.MaxValue/1000; порог в квантах влияния × секундах |
| DominanceMargin | 1000 | long ≥0; необходимо строгое превосходство сверх него |
| ProgressDecayPerSecond | 2000 | long ≥0, ≤ long.MaxValue/60000; скорость затухания прогресса |
| LinkDistance | 60 | Конечное >0; расстояние ребра узел–узел и корень–узел |
| MaximumHops | 8 | Целое ≥1; переход от корня тоже считается |
| ShockCanRelay | true | Независимый допуск Shocked в граф |
| PanicCanRelay | false | Независимый допуск Panicked в граф |
| IsolationDelayTicks | 12 | Целое ≥1; подтверждение непрерывного закрытия пути |
| RecoveryDelayTicks | 8 | Целое ≥1; устойчивое восстановление |
| SeverityPerSecond | 0.03 | Конечное ≥0; скорость нарастания шкалы тяжести |
| SupportedSeverityMultiplier | 0.25 | [0,1]; влияние оперативной поддержки на тяжесть |
| SuppliedSeverityMultiplier | 0.5 | [0,1]; независимое влияние снабжения |

Профиль содержит UnitId (целое, уникальное), Role, CanCaptureTerritory, CanRelay, TypeCoefficient (конечное ≥0), InfluenceRadius (конечное >0) и MinimumRelaySoldiers (uint). Для недопустимых ролей CanCaptureTerritory=true вызывает ошибку. Все названия Role фиксированы enum: Line, Reserve, Airborne, SpecialForces, Recon, Sniper, Vehicle, Other. Настройки техники пока выключены в example; тест демонстрирует только возможность явного opt-in.

Дополнительный StatusCoefficient задаётся нормализованным снимком подразделения: конечное ≥0. Значение 0 выключает территориальную эффективность и relay. AliveSoldierCount имеет тип uint. Состояния Loaded/Deserting/Alive передаются отдельными признаками, не спрятанными в численном коэффициенте.

Геометрия задаётся конструктором TerritoryGrid: Width/Height >0, не более 4 000 000 ячеек; CellSize конечный >0; Origin конечный; длина маски равна Width×Height. Размер ячейки и расстояния должны использовать одну систему координат. Корни задаются массивом TeamRoot в доступных клетках; внутренние Team=0/1. Профильные радиусы не зависят от процента HP.

Для тестового GridRetreatAccess явно задаётся enemyControlBlocksRetreat. Это отдельное правило маршрута, не вывод из оперативной связанности. Политика отображения задаётся ITeamKnowledgePolicy; по умолчанию запрещены все клетки/границы. Маски, корни, период расчёта и каталог не следует менять посреди симуляции без новой инициализации.

Произвольно огромные коэффициенты не являются поддерживаемым балансом: checked-арифметика останавливает переполнение. Авторитет должен валидировать конфигурацию и входные данные до запуска матча. Текущий API ориентирован на доверенные внутренние снимки и не заменяет валидацию произвольных сетевых пакетов.
