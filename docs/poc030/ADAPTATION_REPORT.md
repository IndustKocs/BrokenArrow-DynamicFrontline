# PoC030 — отчёт адаптации по UA01

Дата: 2026-10-29. Ветка `feature/poc030-ua01-two-client-runtime`, база `a5f1745fa26cc6171150db37805fe8731b2261bc`.

**Результат: частично реализованный диагностический кандидат. Полная приёмка ТЗ16 заблокирована.** `PreparedForTwoClientProbe=false`, `ObservationValidated=false`, `EffectsValidated=false`, `FullModeValidated=false`. Это не готовый режим Dynamic Frontline и не завершение всех требований A–D.

Собран настоящий MelonLoader-плагин 0.3.0 с самостоятельным входом через `GameController.Instance`, чтением часов/паузы/текущего игрока, обходом `GameContext` и чтением компонентов только после проверки владельца. Читаются локальный ECS-ключ, сетевой NetID-кандидат, HP, стресс, исходный MaxStress загруженного UnitData, Role, число бойцов и позиция. Никаких native writers, Harmony patches или игровых RPC в новом плагине нет. Свой GUI.Box показывает режим, качество данных, собственное количество и состояние связи. При несовместимом interop он остаётся выключенным.

Повторно проверены полные хеши GameAssembly/metadata/UnityPlayer/EXE: текущая установка соответствует UA01, Build26273833. В отдельный output создано 168 новых interop-сборок из фактической новой пары; 14 групп используемых членов проверены в созданных сборках через AsmResolver, без исполнения игровых классов. Это не runtime-валидация generic/ref access.

Служебный TCP-канал использует HMAC, случайные connection nonce, отдельный session ID, последовательности и ограниченный кадр. Два отдельных процесса обменялись статусами на localhost. **Канал пока передаёт только статусы; канонический мировой поток, owner union, delta/resync не реализованы.** Совпадение статусов не доказывает согласованность мира.

Сохранены весь прежний Core/Frontline/Integration и `Legacy_022`. Проверки исходной ветки повторены: 356/356; новые автономные проверки — 44/44. Добавлены отдельные модели потокового обслуживания, binding epoch и журнала эффектов; они не подменяют отсутствующие native sources и не подключены к игровым записям.

Архив включает свои DLL, конфигурацию с запретом runtime-чтения до отдельного разрешения, контрольные суммы, инструкции и скрипты. Генерированные игровые обёртки, оригинальные DLL/metadata/ресурсы, SDK, MelonLoader и секреты в архив не входят. Установка/удаление проверяются только в искусственном каталоге. Launcher, исследования UA01 и рабочие ветки не изменялись; игра и модлоадер не запускались.

Незакрытые части: полный фазово-согласованный roster; canonical spawn generation; активная база/Buff; реальные terrain/root/mask/nav; подтверждённые service receipts; raw combat stress; native score; канонический транспорт; игровые уведомления/круги; полномочия эффектов; полный нагрузочный soak. Их причины и следующие шаги приведены в OPEN_DECISIONS_AND_BLOCKERS.md. Не выдавать этот архив за полностью готовый первый матч из ТЗ16.
