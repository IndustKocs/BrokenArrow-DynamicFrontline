# Первый опыт A/B — план, не разрешение запуска

Статус сейчас: **не выполнять игровой опыт до закрытия blockers readiness и отдельного согласия обоих участников**. Нет требования сначала играть одиночный матч. Этот документ задаёт будущую одновременную двухклиентную пробу и критерии остановки.

1. На каждой машине отдельно подтвердить разрешение на подготовку loader/установку/запуск. Зафиксировать проверенный предусмотренный игрой способ закрытой незашищённой тестовой сессии. Название Custom само по себе этого не доказывает. Не менять launch options, античит, защиты ОС или аккаунты.
2. Проверить SHA zip, payload-manifest, preflight-runtime по четырём файлам и SteamManifest BuildID. Loader0.7.3/Interop1.5.1 — сверить точные зависимости. Согласовать новый interop cache и его файловый план отдельно; текущий installer cache не устанавливает. Старая или смешанная пара — STOP.
3. Выбрать одну реально доступную карту, зафиксировать сценарий/базу/Buff, bounds/roots/scoring mask/nav revision. **Карта пока не выбрана: нет проверенного map descriptor. Не использовать выдуманный прямоугольник.** Для кандидатов: A — Mech. Riflemen57+Marines59; B — Motopekhota60+VDV DSh1 108; транспорт BTR82 ID1/BMP3 ID3 и отрицательный Tank ID9. Доступность в выбранном профиле/колоде проверить; извлечённая таблица этого не гарантирует.
4. Вне игры сформировать plan каждого компьютера через prepare-dev-install -Plan. Показать конфликты и removal plan. После отдельного согласия — apply-dev-install. Исходный probe.json безопасен: RuntimeReadAuthorized=false, NetworkEnabled=false. После согласия на конкретную пробу выставить только ObserveTwoClient, RuntimeReadAuthorized/PrivateSessionConfirmed=true. Присвоить общий новый Session UUID и разные роли A/B. Secret — случайные32bytes, передать второму участнику вне логов/чата отчёта; SecretFile локальный. Host — LAN адрес A, явный порт; никаких автоматических firewall правил.
5. A начинает слушать, B подключается в60s. Если runtime loader/interop не совпадает или HUD/reader недоступен, завершить опыт и собрать причины, не обходить gate. Порядок входа в игровой матч должен учитывать окно подключения; автоматического reconnect нет.
6. В закрытом матче оба отмечают начало, pause/resume, spawn своих разрешённых Line/Assault, погрузку/выгрузку, бой/потери и штатное обслуживание. Сравнить отображаемые owner/count/HP/stress с наблюдаемой игрой. Не включать effects. Нет требования побеждать или менять native objectives/economy/endgame.
7. STOP: чужой owner в own trace; смешанный interop; nonfinite values; старый session после выхода; runaway memory; unexpected writes; disconnect; native session type не подтверждён. Incomplete/Unknown не считаются доказательством котла или отсутствия армии.
8. Закрыть игру штатно. Каждый локально запускает collect-two-client-logs; отправлять только очищенные журналы. Сравнить compare-two-client-session и заполнить TWO_CLIENT_RESULT_TEMPLATE. Результат header/status не повышает ObservationValidated автоматически. Фиксировать Fail/Unknown/NotMeasured буквально.

Сейчас отсутствуют shadow geometry/notice/ZOC UI и canonical world channel. Поэтому перечисленные в ТЗ16 проверки кольца, двух pockets, hidden partner600, loss of contact, raw stress/recovery/positive service, full match score/endgame **не могут быть засчитаны этой версией**. Их нужно добавить после устранения технических blockers, до заявления PreparedForTwoClientProbe для полного ТЗ. Для EffectsTest нужны отдельные proven contracts и новое согласие/матч; конфиг не включает writer.
