# Full-debug5 — исправления аварии и Workshop

## Разбор падения

В двух локальных дампах восстановлен одинаковый managed stack: NativeContext.Read → LobbyState.get_Options → Il2CppObjectPool.Get → il2cpp_object_get_class. Сигнатура Windows: coreclr.dll 6.0.36, 0xc0000005, offset 0x1d4089. У второго тестировщика совпадает сигнатура Windows; его дамп не исследовался.

В full-debug4 NetworkLobbyService.get_State перехватывался postfix. Cpp2IL metadata подтверждает RVA 0xB7F0, длину 5 байт и 1540 методов с тем же адресом. Это небезопасный детур: getter свёрнут компилятором с посторонними методами, поэтому захват мог сохранить посторонний объект как lobbyService. Перехват удалён. Теперь используются .ctor (0x652490), Connect (0x64F340), Dispose (0x64FC10); у каждого ровно один адрес в метаданных поддерживаемой игры. Initialize также нельзя использовать: это короткая заглушка.

Capture проверяет тип, Dispose очищает только текущий экземпляр по Pointer; старый сервис не очищает заменивший его новый. Вычислительное ядро, Steam transport, политика защищённых сессий и HUD не перерабатывались. Отсутствие lifecycle-события оставляет HUD в ожидании, без небезопасного fallback к getter.

Проверка уникальности включена в свежую генерацию interop. Контрольный запуск проверки старого getter завершается отказом. Проверка IL собранного plugin запрещает возврат к get_State/Initialize. Источник методики анализа: https://learn.microsoft.com/en-us/dotnet/core/diagnostics/dotnet-dump . Сырые дампы и память не входят в поставку.

## Workshop

Поддержаны авторская Scenarios/5454584 и подписанная steamapps/workshop/content/1604270/3830189668 в библиотеке игры. Проверяются оба файла вместе, конфликты и неполная загрузка отвергаются. Исходный совокупный SourceSha256 сохранён, метаданные карты не заменялись. Фактические файлы Workshop пользователя совпадают с ранее проверенным сценарием. Другие библиотеки для вручную перенесённой подписки пока не сканируются.

## Лаунчер

Новый public launcher получает текущий Release при Install без требования GitHub token. Нет скрытого отката к embedded версии при сетевой ошибке. Старый launcher EXE не обновляется автоматически: его нужно заменить либо применять только Update. Транзакционный installer/rollback сохранён.

## Проверки

Steam 95/95, RC2 54/54, RC1 44/44, Simulation023 72/72 (265). Дополнительно: pointer repair fixture, metadata MelonGame, IL запрет общего getter, положительная проверка трёх уникальных адресов и отрицательная проверка get_State. Новые тесты покрывают Workshop-only, missing/incomplete, изменение исходников, одинаковые и конфликтующие копии.

Результаты свежей генерации interop и sandbox-поставки записаны в evidence/t18-debug-launcher/full-debug5-validation.json. Игру не запускали; мод в настоящую установку не устанавливали. Удаление дефектного детура подтверждено статически, прекращение реальных крашей ещё НЕ подтверждено.

## Обязательные runtime-проверки после отдельного разрешения

1. На обоих ПК одинаковый full-debug5, HUD виден; меню, сворачивание и возврат без падения.
2. Подписанный сценарий найден без копирования. Приватное Scenario-лобби захвачено через уникальные lifecycle hooks; выход и повторный вход не оставляют старый сервис.
3. LoadReadProbe на обоих ПК: свои юниты, посадка/высадка, уничтожение; без преждевременного roster confirmation.
4. Steam Relay и совместимость, GamelogMarkerConfirmed, дальнейший ObserveTwoClient и resync — только после успешного probe.

При новом краше остановить тест, сохранить безопасный экспорт и сведения Application Error. Повторная переустановка не является диагностикой.
