# Установка для двух тестировщиков — FullDebugView + Launcher

Пока только поставка: запуск игры и установка мода в настоящую игру требуют отдельного разрешения.
Обоим игрокам передаётся один и тот же DynamicFrontlineLauncher.exe. Он содержит одинаковую сборку 0.4.0-T18-full-debug7. Не пересылайте interop, local-preparation или чужие ключи.

1. Сохраните EXE вне игровой папки и откройте его. Нужны Windows x64 с штатным .NET Framework 4.5+ (Windows 10/11), интернет для зависимостей и достаточно места для локальных инструментов/interop.
2. Лаунчер ищет Steam по HKCU/HKLM и libraryfolders.vdf. Если путь пуст — нажмите «Папка…» и выберите Broken Arrow. Проверка совместимости выполняется перед изменениями; несовместимая версия останавливает операцию.
3. После отдельного разрешения закройте игру, нажмите «Установить» и подтвердите конкретную папку. Portable PowerShell, pinned MelonLoader и инструменты загружаются автоматически с проверкой хешей. Interop создаётся на этом ПК. Недостающий общий Microsoft Desktop Runtime может запросить системное повышение прав. При ошибке не отключайте проверки.
4. Дождитесь завершения и нажмите «Проверить файлы». До завершения операции окно не закрывается штатной кнопкой; после аварии используйте «Восстановить после сбоя».
5. Игра автоматически НЕ запускается. После отдельного разрешения запускайте её через Steam: Anti-Cheat Disabled, штатный приватный Scenario 5454584/Airbase; параметры запуска `--melonloader.agfoffline --melonloader.agfvdumper 2022.1.0-pre-release.21`.
6. Сначала на обоих ПК LoadReadProbe, сверка собственных юнитов/посадки/смерти/spawn/реального HP и стресса, GamelogMarkerConfirmed. Только затем оба подтверждают roster.
7. По умолчанию TeamSafe. Для полного вида каждый отдельно нажимает в HUD «I CONSENT to sharing HIDDEN DATA». FullDebug включается только при двух согласиях и двух подтверждённых roster. Постоянный индикатор FULL DEBUG предупреждает, что скрытые данные раскрываются.
8. Любой игрок может отозвать согласие. Старый обмен и изображение сбрасываются; начинается новая TeamSafe-сессия. При выходе из companion lobby согласие теряется. Новому участнику требуется новое согласие. Нельзя отозвать данные, которые второй игрок уже увидел.
9. После теста нажмите «Собрать логи». Передайте только export-папку, указанную в журнале. Не отправляйте сырой Gamelog, Latest.log, токен GitHub или каталог подготовки.

## Лаунчер 0.4.1: постоянный EXE

Один раз скачайте лаунчер из релиза v0.4.1-launcher-auto1 или более нового. Сохраните вне игры и создайте обычный ярлык. При каждом открытии он проверяет публичный GitHub Releases. Новую версию EXE загружает в `%LOCALAPPDATA%/DynamicFrontlineLauncher/launcher-updates/<SHA256>/`, проверяет SHA256 и размер, открывает новую версию и закрывает старое окно. Сохранённый EXE остаётся постоянной точкой запуска и больше не требует ручной замены.

Мод не обновляется автоматически: для него нажмите «Обновить» и подтвердите операцию. Игра не запускается. При недоступной сети или ошибке проверки текущий лаунчер остаётся доступен для проверки файлов, удаления и восстановления. Повреждённый кэш не запускается. Приватный канал автообновления EXE пока не поддерживается; наш репозиторий публичный.

В старом лаунчере 0.4.0 нет этого механизма, поэтому только переход на 0.4.1 требует однократного скачивания.

## Обновление full-debug7

Репозиторий IndustKocs/BrokenArrow-DynamicFrontline публичный; GitHub-токен не нужен. Оба тестировщика используют одинаковый prerelease. Новый лаунчер при «Установить» и «Обновить» получает текущий опубликованный пакет с проверкой SHA256. При сетевой ошибке он останавливается, а не устанавливает незаметно старый встроенный пакет. Старый EXE можно использовать через «Обновить», но его кнопка «Установить» по-прежнему может вернуть встроенную старую версию — замените сам EXE новым.

Сценарий устанавливается вместе с full-debug7. Подписка на Workshop item 3830189668 остаётся дополнительным способом получения. Мод ищет `steamapps/workshop/content/1604270/3830189668` в библиотеке установленной игры. Ручное копирование в `Scenarios/5454584` не требуется. Локальная авторская копия также поддерживается. Если обе копии существуют, они должны совпадать; частичная загрузка, конфликт или изменённые контрольные суммы блокируют запуск мода. Не копируйте чужой interop. Перенесённый вручную Workshop вне библиотеки игры пока не обнаруживается.

После обновления нажмите «Проверить файлы». Первый разрешённый запуск: сначала проверить HUD full-debug7, ожидание лобби, сворачивание/возврат и отсутствие краша. Затем приватный Scenario 5454584, по одному игроку на противоположных сторонах, LoadReadProbe. До сверки roster обоими игроками не подтверждайте его и не включайте ObserveTwoClient. Автономные тесты не подтверждают стабильность настоящего матча.

Кнопка «Собрать логи» создаёт папку `export-ДАТА-ВРЕМЯ` внутри каталога preparation в `%LOCALAPPDATA%/DynamicFrontlineLauncher`. Передавайте её содержимое, а не полный каталог preparation. Дампы остаются локально.

## Ошибки и удаление

Повреждённый или чужой loader/DLL не перезаписывается молча. «Восстановить после сбоя» обрабатывает незавершённый журнал, а не разрешает замену неизвестных файлов. Повторная установка может восстановить отсутствующие собственные файлы; изменённые неизвестные файлы требуют разбора.

«Удалить» спрашивает согласие. Флажок сохраняет копию настроек вне игры; снятый флажок разрешает транзакционное удаление принадлежащих моду настроек. Сторонние файлы и автоматически созданные runtime-логи не удаляются. Общий системный runtime сохраняется. Исходные общие файлы восстанавливаются из проверенных резервных копий.

EXE пока не имеет Authenticode-подписи. Сверяйте SHA256 с поставкой доверенного автора. PowerShell-команды для обычной установки не требуются; START.ps1 остаётся резервным инструментом разработчика.

## Интерфейс лаунчера 0.4.2

Главный экран: карточка тестовой сборки, большая кнопка «Установить мод» / «Обновить мод» (при незавершённой транзакции — «Восстановить установку»), проверка обновлений и файлов. «Настройки» открывают выбор папки игры, автоматический поиск, восстановление и удаление. Предупреждение о запуске через Steam в режиме Anti-Cheat Disabled видно на обоих экранах. Кнопки запуска игры нет.

«Логи игры» открывает `<папка игры>/GameLogs`; «Логи мода» — `<папка игры>/UserData/DynamicFrontlineSteam/logs`. Отсутствующие папки не создаются, выводится сообщение. «Экспорт диагностики» по-прежнему создаёт очищенный экспорт для передачи разработчику.

Пользователю лаунчера 0.4.1 достаточно закрыть и снова открыть тот же EXE или ярлык: внешний вид 0.4.2 доставляется автообновлением. Сборка мода остаётся full-debug7.

## Проверка full-debug7

При старте ожидается `Connect/Dispose handlers registered; native lobby observation pending`. Это регистрация обработчиков, не подтверждение игрового подключения. Создайте или войдите заново в приватное Scenario-лобби 5454584: после чтения и проверки появляется `DF private Scenario lobby observed and validated`. Пока HUD сообщает `Waiting for native lobby Connect event`, работа мода с матчем не подтверждена. При зависании в этом состоянии сохраните диагностику; не подтверждайте roster и не переходите к ObserveTwoClient.

Предупреждение про NetworkLobbyService::.ctor устранено удалением неподдерживаемого перехвата. Общее предупреждение Il2CppInterop `Class::Init signatures ... substitute` этим исправлением не скрывается и может оставаться. Реальное прохождение Connect на обоих ПК ещё требуется проверить.

## Сценарий в пакете full-debug7

При «Установить/Обновить мод» в `Scenarios/5454584` автоматически устанавливаются `5454584.bascr` и `meta.json`. Airbase уже есть в игре; файлы самой карты не распространяются. Подписка на Workshop не обязательна.

Если оба файла уже существуют и совпадают, они используются как чужая/авторская копия: установщик их не переписывает, не получает права обновлять и оставляет при удалении. Если файлы отличаются или один отсутствует, операция останавливается с `AuthorScenario5454584Preserved_ConflictingOrIncompleteCopy`. Не удаляйте и не заменяйте авторскую копию ради прохождения проверки: сохраните её отдельно по собственному решению; автоматического перезаписывания нет.

Если сценарий первоначально поставил лаунчер, неизменённые файлы обновляются по квитанции и удаляются при удалении мода. Если вы отредактировали хотя бы один из них, автоматическое обновление блокируется, а удаление сохраняет оба файла и сообщает конфликт. Сбой посередине установки/обновления откатывается через «Восстановить после сбоя»; новая установка откатывается к отсутствию обоих файлов, обновление — к прежней паре.

Workshop-копия не изменяется. При несовпадении Workshop и локального сценария runtime-проверка по-прежнему блокирует мод. Изменение сценария в будущей поставке требует согласованного MapDescriptor, старые хеши не обходятся.
