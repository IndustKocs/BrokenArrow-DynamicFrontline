# Dynamic Frontline 0.4.0 — подготовка к первому 1v1, ревизия preflight2

Дата: 2026-10-30. Основа: 3b1e326. Реальных игровых испытаний нет.

## Закрытые замечания

1. Result больше не помещается в detail и не обрезается. Все шесть StageDigests,
   InputId, SessionHash, ResultSource и разрешённые числовые метрики сохраняются
   структурированно. Отдельная очередь на 512 результатов не использует частотный
   фильтр обычных сообщений; переполнение останавливает наблюдение с DiagnosticLoss.
   JSONL ротируется по 16 MiB вместо прежнего молчаливого прекращения записи.
   В Gamelog полная запись Result может поступать с частотой до 4/сек; резерв сохраняет все.
2. В TeamSafe клиент B записывает CoordinatorReceipt: полученные контрольные суммы
   и проверенную целостность именно своей проекции. Это НЕ независимый расчёт скрытого
   мира. Compare различает Coordinator/Independent/CoordinatorReceipt, сопоставляет
   session+input, сообщает пропуски, порчу и несовпадения. Совпадение чек-сумм не является
   подтверждением полного игрового опыта (CompleteSessionVerified=false).
3. Экспорт — конструктивная типизированная схема. Никакого копирования raw JSON,
   detail, исключений, Loader.log, replay, координат, участников, имён, SteamID,
   путей, временных меток или конфигов. Имена файлов заменяются порядковыми.
   Сохраняются криптографические контрольные суммы и псевдоним текущего матча,
   необходимые для сравнения; это не обещание анонимизации произвольных данных.
   Старый усечённый Result/невалидный JSON помечается DiagnosticLoss; отчёт Complete=false.
4. Steam Messages сохранён. До discovery/создания сессий задаётся ICE_Enable=0,
   значение читается обратно и проверяется перед send/receive. Connected route должен
   быть encrypted/authenticated, Relayed и иметь SDR relay POP. Неизвестная политика,
   сбой API, изменение значения или direct route прекращают DF; fallback отсутствует.
5. START.ps1 автоматизирует обнаружение игры, сверку пакета/игры, pinned dependencies,
   portable runtime, свежую генерацию interop, loader/mod manifest и план установки.
   Prepare пишет только вне игры. Install/Remove/Recover требуют явного ключа согласия.
   Pinned loader включён в прежний транзакционный installer: WAL, hash guards, backup,
   restore. Чужой version.dll блокирует установку. Старый RC2, ядро и HUD сохранены.

## Автономные проверки

- 33 проверки Steam/исправлений: полный путь к двум графическим проекциям, Result на
  обоих клиентах, 400 полных событий без усечения, экспорт с canary-секретами/ID/миром,
  сравнение исходных/экспортированных данных, контексты матчей, неполные записи,
  переполнение и Relay-only fail-closed.
- RC2: 51/51; RC1: 44/44. Изменён только старый тест экспорта, чтобы требовать новые
  обезличенные имена и отдельный выходной каталог вместо раскрытия исходного имени.
- Полная Prepare с новой генерацией interop из локальной игры выполнена без установки:
  проверены 30 контрактов чтения, создан план на 455 файлов; WritesToTarget=0.
- Sandbox A: Prepare/Install/Verify/Remove всего мода и pinned loader.
- Прерывание полной установки после замены version.dll: Recover восстановил исходный proxy и удалил новый plugin.
- При остановке worker завершается до закрытия журнала; очередь Result дописывается полностью.
- Sandbox B: восстановлены прежние version.dll, interop и Config.cfg после удаления.
- Негативные проверки: отсутствие разрешения, изменённая dependency, чужой loader — отказ.
- Portable .NET 6.0.36 получен с официального источника и проверен SHA512. Остальные
  инструменты в автономном прогоне взяты из проверенного локального cache. Загрузка
  всех dependency URL на другом ПК не объявляется проверенной.

## Что ещё не проверено

Настоящий Steam/SDR маршрут, вызов native Steam ABI в процессе игры, видимость HUD,
Gamelog-файл и корректность roster двух игроков — NotRun. System Desktop Runtime
installer не запускался: нужная версия уже есть на стенде. Его ветка проверяет pin,
код завершения и наличие runtime, но реальная системная установка требует отдельного
разрешённого запуска Install на ПК, где эта зависимость отсутствует.

Политика ICE — process-global default: Messages API не предоставляет pre-creation
параметр отдельно для сессии. Значение 0 сохраняется до завершения процесса игры,
включая Stop DF; оно не записывается в Steam preferences. Это может ограничить direct
маршруты других новых Steam Networking соединений этого процесса. Подробнее в
STEAM_RELAY_POLICY.md. Никакой API античита не меняется.

Общий Microsoft Desktop Runtime, если впоследствии установлен с согласия, не удаляется
при откате мода: он может требоваться другим программам. Файлы мода/loader и прежние
общие interop/config обрабатываются по receipt. Новые runtime-логи не удаляются.

Игра не запускалась, в настоящую игровую папку ничего не установлено. Все критерии
игровой приёмки остаются открытыми до первого приватного 1v1 на двух ПК.
