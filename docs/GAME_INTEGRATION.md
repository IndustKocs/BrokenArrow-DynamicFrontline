# Граница интеграции с Broken Arrow

## Чтение ECS

`ReflectionUnitReader` — реальный экспериментальный код чтения через runtime reflection. Его проверили на управляемых тестовых типах, но **не на игровых IL2CPP-обёртках**. Доступ устроен так:

1. Передать существующий `LuaUnit` своей части через `IUnitBindings`; ключ включает матч, UID и поколение сущности.
2. Проверить `GetOwnerPlayerUID()` до чтения позиции и компонентов.
3. Проверить UID, `Entity.IsAliveVersion` и `LuaUnit.IsAlive()`.
4. Получить `InfantryUnitComponent`, `UnitComponent`; сверить `UnitComponent.Owner.UID`.
5. Прочитать `UnitComponent.UnitData.Id`, `AliveSoldierCount`, `StressComponent`, `CommandsComponent.CurrentCommand` и позицию.
6. Сохранить только неизменяемый DTO; не сохранять компоненты, native pointers или ref-ссылки между кадрами.

`UnitComponent`, `InfantryUnitComponent`, `StressComponent` — структуры. Копия допустима для одноразового снимка чтения; запись в такую копию не изменит мир. Код не пишет в компоненты и не использует смещения полей. `CommandsComponent` — класс; считывается только имя типа текущего приказа. `ToString()` приказа не вызывается, чтобы не выводить сведения о скрытой цели.

Восстановленная сигнатура `DefaultEcs.Entity.Get` не является гарантией формы runtime-обёртки. `MakeGenericMethod`, boxing и ref-return могут отличаться или не поддерживаться. Любая несовместимость отключает экземпляр адаптера. Следующий этап должен проверить сгенерированные IL2CPP-обёртки и заменить reflection типизированным чтением там, где это нужно.

Название `UnitData` неоднозначно: `BrokenArrow.MissionEditor.Data.Unit.UnitData` — редакторские данные, а `UnitComponent.UnitData` имеет тип таблицы `Units`. Для диагностического Unit ID выбран второй путь (`Id`); UID живого отряда берётся отдельно из LuaUnit. Подменять их друг другом нельзя.

Не реализованы автоматическое получение локального игрока, перечисление его LuaUnit, выбор текущего отряда, надёжное определение поколения UID, стартовой зоны и результата pathfinding. Для них оставлен `IUnitBindings`. Прикрепление к плагину возможно через `AttachReadOnlySession`, но сам плагин такой provider не создаёт. Это явная незавершённая граница интеграции.

## Команды и перехваты

| Точка | Найденное назначение | Решение PoC |
|---|---|---|
| `BaseCommandSystem.AddCommandsQuery(Func<Entity,ICommand>, bool, Entity, Nullable<Vector3>)` | Обработка одной сущности | Подготовлен неустановленный Harmony-prefix в `CandidateOrderHook` |
| `BaseCommandSystem.UpdateCommandsQuery` | Групповой путь | В native/ISIL-дампе есть вызов AddCommandsQuery для сущностей; фильтр проверять для каждого участника группы |
| `MainCommandSystem` | Пользовательские движение/атака/погрузка и другие действия | Требуется аудит всех UI/горячих клавиш, очередей и альтернативных систем |
| `CommandsComponent.CurrentCommand` | Общая установка приказа | Не перехватывать глобально: потеряется происхождение команды |
| `EntitiesHelper.CancelCommand(in Entity, bool clearQueue, ...)` | Отмена и очистка очереди | Альтернатива LuaUnit.StopAllCommands после проверки сигнатуры и режима очистки |
| `EntitiesHelper.CreateMoveCommand(in Entity, in Vector3, PathfindingMethod, RulesOfEngagementEnum, ...)` | Создание команды движения | Само создание не означает постановку в очередь; не вызывать без исследования пути отправки |
| `MoveToPositionCommand(Vector3, Nullable<float>, bool)` | Команда физического движения | Кандидат для типизированной интеграции; pathfinding/активация требуют проверки |
| `NetworkCommandService.IncomingCommand`, `IncomingCommandComplete`, `SetRemoteCommand` | Входящие/удалённые команды | Не устанавливать блокировку пользовательского ввода здесь |
| `LuaUnit.StopAllCommands`, `MoveTo(Vector3,int,bool)` | Сценарный путь отмены и движения | В адаптере подготовлен вызов с attackMove=false, но выполнение отключено |

Доказательство группового пути: `research/native_analysis/IsilDump/BrokenArrow/BrokenArrow/Client/Ecs/Commands/Systems/BaseCommandSystem.txt:2051` относительно родителя проекта. Сигнатуры — в параллельном `research/signatures/DiffableCs`.

`UserCommandGate` принимает исключительно пользовательские запросы и фильтрует группу по отдельным ключам. Внутреннее движение контроллера идёт через отдельный IGamePort, без доступного игроку переключателя «это внутренний приказ». Сетевые/системные коррекции вообще не проходят этот gateway.

Для реального Harmony-prefix всё ещё нужно доказать, что выбранная точка является именно границей пользовательского ввода. Если LuaUnit.MoveTo попадает в тот же метод, потребуется внутренний scoped-контекст на основном потоке с гарантированным снятием в finally. Если есть альтернативный пользовательский путь, добавить фильтр и там. Не включать управление до проверки полного покрытия; текущий код намеренно не заявляет, что одна точка покрывает всё.

`CandidateOrderHook` не имеет атрибутов автопатчинга, не регистрируется и не модифицирует игру. `HarmonyDontPatchAll` запрещает автоматическую установку. `ReadyForControl` жёстко false: одного изменения настройки Debug недостаточно для выдачи приказов.

Нет вызовов ReturnToBase, refund/despawn, передачи владельца боту, изменения здоровья/стресса или неуязвимости. При ошибке новая команда не выдаётся, локальная блокировка снимается; ранее начатое движение может продолжиться, пока пользователь не задаст другой приказ. Это сознательная политика отказа PoC.
