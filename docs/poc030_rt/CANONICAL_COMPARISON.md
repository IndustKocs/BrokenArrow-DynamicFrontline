# Сравнение канонических результатов

Дата: 30.10.2026. Пакет RC2: commit `007f943fb079c1862af9fe128b22d8d4d08e23da`. **Prepared / Runtime NotRun**. Настоящая игра, MelonLoader и сетевой матч не запускались; игровые файлы не изменялись.

Статус NOT_RUN; игровых пар входов нет. Compared не вычислялся. Синтетические логи прежних этапов не являются runtime evidence.

Перед compare вручную проверить sidecar-контекст A/B: один PackageHash, Session, этап, match binding, map/profiles/rules/ABI и совместимые Epoch/revisions. CLI RC2 сопоставляет Result по InputId и сам не доказывает принадлежность файлов одному матчу. Никогда не объединять разные сборки/сеансы.

Использовать existing collect/compare/replay/metrics согласно runbook. Для каждого общего InputId сначала сравнить Digests.Input: расхождение классифицировать InputMismatch. При одинаковом Input сравнить остальные stage digests и перечислить конкретную стадию. Сохранить OnlyA/OnlyB; Passed требует Compared>0. TeamSafe не доказывает независимый полный пересчёт B.

Detailed replay требует отдельного согласия обоих на скрытый мир, короткого окна и отдельного хранения. Стандартный collect исключает ReplayInput/ReplayContext/PositiveServiceOperation и файлы ключей/конфигов. Он фильтрует виды записей, не является универсальным DLP: перед передачей вручную проверить разрешённые записи на неожиданную приватную информацию. Ошибки loader сохранять только минимальными очищенными фрагментами, не сырым Gamelog.
