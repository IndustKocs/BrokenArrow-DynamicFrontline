N00: LobbyType.Scenario=2; Custom=1 — иной тип. ProtectedLobbyTypes приходит с обычной авторизацией; native GetBlockReason учитывает этот список. Отсутствие ошибок, приватность лобби и отсутствие рейтинга не доказывают выключенную защиту. Штатный Scenario может пользоваться официальной авторизацией и сервером — DF TCP не создаёт общий игровой мир.

После отдельного согласия обоих владельцев:

1. До запуска проверить на обоих ПК build/hash и отсутствие загружаемых DF/MelonLoader в baseline. Чужую существующую установку не удалять автоматически; сначала согласовать её отдельный обратимый откат.
2. Зафиксировать точное имя официального варианта запуска для сценарного моддинга и документированное основание. Не придумывать параметры отключения EAC. Если путь/допуск неоднозначен, остановить R0.
3. Используя только штатный клиент, проверить доступность Scenario и текущую защиту. Не менять ProtectedLobbyTypes/GetBlockReason, не извлекать tickets, не отправлять собственные auth/RPC. Не публиковать сырые Gamelog. При невозможности безопасно установить политику — BLOCKED; можно подготовить запрос издателю, но не отправлять его без поручения.
4. Только после R0 PASS: приватный Scenario Airport/Airport_network, ровно два человека, противоположные стороны, без ботов/наблюдателей. Наличие 10 слотов статического сценария не доказывает возможность 1v1. Если Start недоступен, сохранить точный штатный отказ, не подменять сценарий.
5. На обоих клиентах подтвердить один матч: появление, движение, урон и завершение. Согласовать время/описание события; не требовать plugin FightId от немодифицированного baseline. Зафиксировать состав и FPS для сравнения.
6. Закрыть обе игры. Записать R0 и R1 раздельно. PASS baseline не подтверждает совместимость конкретного MelonLoader.
