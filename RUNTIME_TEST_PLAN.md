# План отдельного read-only runtime-испытания

Этот план не выполнен. В рамках PoC 0.2 игра не запускается и сборки не устанавливаются. Runtime требует отдельного разрешения пользователя.

1. Зафиксировать версию игры, SHA256 критических файлов, loader, interop assemblies, scenario DB и конфигурации профилей. Сопоставить с manifest. Сначала проверить выключенный loader в согласованной тестовой среде; изменения файлов и способ восстановления заранее перечислить.
2. Установить полный источник lifecycle, не visibility-driven spatial tree. Проверить spawn, despawn, смерть, Death/Dead/RemoteDeath, revive, смену owner, transport load/unload, потерю/возврат видимости, повторное использование NetID, конец матча и reconnect. Вести собственное поколение. Пропуск сущности допустим как despawn только у подтверждённого полного census.
3. Определить поток и фазу согласованного чтения. Сопоставить LuaUnit/Entity/NetEntity/RootEntity без предположения равенства UID. Проверить position source и возраст значения. Подтвердить здоровье, alive soldiers, stress и desertion без вызовов setters.
4. Подтвердить PlayerUID → TeamUID → side на 5v5; проверить neutral и spectators. Извлечь активную DB с приоритетом scenario db.zip, проверить реальные Units.Id/Role и hash. Настроить только явно разрешённые профили. Сверить origin/scale XZ, обратное преобразование, маску карты, защищённые spawn cells и корни обеих команд.
5. Подключить ограниченный backend навигации. Проверить каждый native status на известных проходимых/непроходимых парах, направление, mask, cost и partial paths. Ненулевой NavPath не доказательство. Для ненаправленного ребра проверить оба направления. Измерить стоимость одного синхронного CalculatePath и общий бюджет на игровом потоке; отдельно проверить поздние ответы и смену map/navigation revision.
6. Разрешить только сбор данных. Проверить полноту и freshness нескольких снимков и отсутствие записи в игровые компоненты. Затем отдельно включить автономную симуляцию; результаты остаются внутри процесса, не влияют на игру. Developer export LiveReadOnly запрещён текущим кодом.
7. Проверить две команды и spectator, скрытые изменения врага, неизменность публичных own-only DTO, независимые часы и постоянный статус ошибок. До расширения FOW проекции подтвердить team-scoped contact API. До сетевой отправки установить авторитет, права sender, reconnect и аудит транспорта.
8. Замерить p50/p95/p99, main-thread time, GC и паузы на реальных 100/300/500/1000 сущностях. Синтетические 24 комбинации не заменяют эти измерения. При перегрузке отключить сбор; не снижать качество проверок ради производительности.
9. Завершить матч/сменить сцену, убедиться в очистке кешей и отбрасывании старых ответов. Повторить fingerprint файлов, сохранить отдельный runtime report с каждым проверенным API и точной версией. Ни один статус не повышать до RuntimeConfirmed только по успешной загрузке DLL.

Критерии остановки: несовпадающая версия/hash, неизвестное обязательное поле, неполный census, противоречивые команды, неверная DB, неустановленный поток, неожиданный setter/команда, утечка скрытых данных или превышение согласованного бюджета. Игровые изменения остаются выключенными на всём испытании.
